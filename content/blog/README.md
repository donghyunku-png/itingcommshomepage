# Blog authoring

`_template.md`를 복사해 한국어 글을 만들고, 같은 slug의 영문 번역을 `en/` 폴더에 만듭니다. 한국어 허용 카테고리는 `회사 소식`, `GEO`, `AX`, `AI 동향`이며 영문은 각각 `Company News`, `GEO`, `AX`, `AI Trends`입니다.

## 게시 순서

1. `title`, `slug`, `category`, `description`, `author`를 작성합니다.
2. 공개일은 `YYYY-MM-DD`, 수정일도 같은 형식으로 입력합니다.
3. 출처는 `sources:` 아래에 `- 출처명 | https://...` 형식으로 추가합니다.
4. 검토 전에는 반드시 `draft: true`로 둡니다.
5. 승인된 글만 `draft: false`로 바꾸고 `npm run build`를 실행합니다.
6. 영문 번역은 수치·조건·한계·출처 링크를 원문과 동일하게 유지합니다.
7. `npm run check`로 메타데이터, 내부 링크, sitemap, 금지된 과장 문구를 점검합니다.

`draft: true`인 글은 생성 페이지·블로그 목록·sitemap·RSS에서 제외됩니다. 그러나 이 저장소나 브랜치가 공개 상태라면, 초안 Markdown을 커밋하고 푸시하는 순간 원문 자체는 외부에서 읽을 수 있습니다. 승인 전 실제 초안은 Git에서 제외된 `content/blog/drafts/` 또는 별도 비공개 작업 공간에 보관하세요. 게시 승인이 끝난 뒤에만 상위 `content/blog/`로 옮깁니다.

비공개 검토본은 저장소 루트에서 `npm run build:review`를 실행하면 `/tmp/iting-site-review`에 생성됩니다. 이 명령은 초안을 `/blog/review/<slug>/` 아래에 `noindex` 페이지로 만들지만, 공개 빌드·RSS·sitemap에는 넣지 않습니다. 이 폴더는 검토용 산출물일 뿐이며 공개 호스팅에 업로드하면 안 됩니다.

이 저장소에는 인증형 CMS를 추가하지 않았습니다. 현재 방식은 별도 계정·OAuth·서버 없이 Git 이력으로 검토할 수 있는 대신, 게시 시 Markdown 편집과 빌드가 필요합니다.

## 대표 이미지와 채널별 재사용

월·수·금 새 기사에는 주제에 맞는 AI 생성 대표 이미지 1개를 준비합니다. 실제 고객·행사 사진이나 실적 증거처럼 보이게 만들지 않으며, 인물·브랜드 로고·수치·읽을 수 없는 이미지 속 글자를 피합니다. 승인된 최종 이미지는 `/assets/blog/<slug>/hero.webp` 등으로 저장하고 한국어·영문 원문에 다음 필드를 넣습니다.

```yaml
image: "/assets/blog/<slug>/hero.webp"
image_alt: "이미지에서 보이는 내용을 설명하는 짧은 대체 텍스트"
image_caption: "AI 생성 일러스트. 실제 고객이나 수행 사례를 나타내지 않습니다."
image_width: "1536"
image_height: "1024"
```

- `image_width`, `image_height`에는 **실제 파일의 픽셀 크기**를 기록합니다. 수치는 예시이며 파일과 맞아야 합니다.
- 한국어·영문은 같은 `image`와 크기를 쓰고, alt·caption은 각 언어로 작성합니다.
- 생성기는 기사 본문, 블로그 목록, 홈페이지 최신 글, Open Graph·Twitter 미리보기와 BlogPosting 이미지에 같은 파일을 반영합니다.
- 과거 글에 이미지가 없으면 기존 로고 미리보기로 동작합니다. 새 기사 이미지 준비에 실패하면 로고를 AI 생성 대표 이미지로 안내하지 말고 게시 전 문제를 해결하거나 검토를 요청합니다.
- 다른 승인된 채널에 재게시할 때도 같은 대표 이미지를 함께 준비하고 채널이 허용하는 크기에 맞춥니다. 플랫폼에서 링크 미리보기만 제공한다면 실제 반영 여부를 확인합니다. 이미지를 생성했다는 사실만으로 채널 게시 완료로 기록하지 않습니다.
- 결과와 자료 공개 권한을 확인한 뒤 `npm run build && npm test`를 실행합니다.
